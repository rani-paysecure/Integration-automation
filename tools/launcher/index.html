Baseline session payment –  customised

          
The sessionUrl is opened in the browser and paid with a test card (Test cards tab); the transaction is then found in the dashboard by session ID. Redirects and callbacks come from the Purchase data tab unless you set them in the session body. the brand ID of the selected tester is sent as the BrandId header and the currency from the Run tab. A session carries no payment method: the Run tab's payment method is clicked on the session page like a customer would.

          
          
          

            
            
          

          
Dynamic values – put these in any field and they are filled in on every run: {{unique}} unique reference · {{uuid}} · {{timestamp}} (epoch seconds) · {{date}} (yyyy-MM-dd) · {{random}} (6 digits) · {{customerId}} (session body only). merchantCustomerId must be unique for every new customer – keep {{unique}} there.

Masking rules customised

            

          
Values that must never be readable in the PSP requests and responses PGS stores for a transaction (dashboard bank record: payment request, refund request, other calls, responses, 3DS). Checked in the PSP checks only (PSP request/response cases and PSP check by ID – not in cashier, S2S, session or refund runs) – a field in clear fails the test and the report shows where it was found, never the value.

          

          

          

        

        

          
How a rule is applied

          
    
            
  1. Pick the payment. General rules apply to every payment, card rules to card payment methods, APM rules only to the payment methods they list (e.g. BANKTRANSFER).
    2. 
            
  2. Find the fields. Each field is recognised by its key names in any stored request / response (nested JSON too) – e.g. Bank account number = accountNumber, bankAccount, acctNo … Add your own key names for anything else (upiId, vpa …).
    3. 
            
  3. Check the value. Masked = ***, xxxx or empty. A readable value fails the check; the test card's full number is also searched for under any key.
    4.
